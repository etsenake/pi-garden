# Pi `ExtensionUIContext` parity manifest

Pi version: `@earendil-works/pi-coding-agent` 0.87.1 (the bundled runtime; `node_modules/@earendil-works/pi-coding-agent/dist/core/extensions/types.d.ts`).

This manifest enumerates every member of Pi's `ExtensionUIContext` for that exact version and assigns each one owner. Pi stays the runtime and source of truth: the driver's [`createExtensionUiContext`](../packages/pi-sdk-driver/src/session-supervisor.ts) hands Pi a `ctx.ui` whose members either map onto a native desktop analogue or return Pi's documented no-op/unsupported result. There is no second extension system; the renderer only sees browser-safe records mirrored per session in [`extension-ui-state.ts`](../packages/pi-sdk-driver/src/extension-ui-state.ts) and [`desktop-state.ts`](../apps/desktop/contracts/desktop-state.ts).

[`scripts/extension-ui-parity.test.mjs`](../scripts/extension-ui-parity.test.mjs) parses the bundled declaration and fails when a member is missing from this table, when a row names a member Pi no longer declares, when a classification is not one of the exact terms below, or when the Pi version above drifts from the installed package.

## Classifications

Every row uses exactly one of these terms:

| Classification                                   | Meaning                                                                                                                        |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| `implemented and verified in Pi Garden`          | Native desktop behaviour predates this parity pass and is covered by regression tests.                                         |
| `implemented by this task`                       | Native desktop behaviour with Pi semantics landed or was completed in this parity pass and is covered by regression tests.     |
| `owned by the interaction system`                | Terminal-only input plumbing; a desktop analogue needs the interaction/adaptation layer, not a `ctx.ui` shim.                  |
| `owned by the theme system`                      | Pi's TUI theme objects; a desktop analogue belongs to the theme work that maps Pi themes onto desktop tokens.                  |
| `owned by rich desktop surfaces`                 | TUI component factories; a desktop analogue is the adaptation of authored components onto rich surfaces, not string rendering. |
| `owned by editor/composer customization`         | Pi editor component and autocomplete extension points; a desktop analogue belongs to composer customization work.              |
| `owned by Adapt for Desktop`                     | Reserved for members whose only path is the Adapt for Desktop programme; none currently.                                       |
| `explicitly deferred: transcript rendering only` | Reserved for transcript-rendering-only families; none currently.                                                               |

## Lifecycle coverage

[`extension-ui-parity.spec.ts`](../apps/desktop/tests/core/extension-ui-parity.spec.ts) drives the native members through real local Pi extensions and checks initial state, update, clear/reset, `/reload`, disabling, removal, session switch, workspace switch, user/global versus project scope, a stale runtime generation and a second window. Runtime disappearance goes through the driver's `reset` request, which drops the per-session record so the renderer falls back to Pi's defaults.
